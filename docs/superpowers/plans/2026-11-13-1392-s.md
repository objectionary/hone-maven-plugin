# The host path of `optimize` hands a relative `target` to `entry.sh`

**Spec:** objectionary/hone-maven-plugin#1392 (issue body)

Without a Maven project `targetOrDefault` (`AbstractMojo.java:215`) returns
`new File("target")`, and `OptimizeMojo.withoutDocker()` (`OptimizeMojo.java:762`,
`:787`, `:793`) passes that string to `entry.sh` as `TARGET`, `INCLUDES` and
`EXCLUDES`. `entry.sh` does `cd "${SELF}"` (line 78) before `[ ! -e "${TARGET}" ]`
(line 93), so the relative `target` resolves inside the temporary script
directory, which has no such folder, and every later `${TARGET}` use (the jeo
`-D` paths, `find`) fails the same way. The Docker path is unaffected because
`mount()` and the container paths use `getAbsolutePath()` (#1034).

## Global Constraints

- `AbstractMojo.targetOrDefault(File)` must return an absolute `File` for both a
  `null` argument (no Maven project) and a relative configured one
  (`-Dhone.target=target`).
- No new file, dependency or wrapper: the fix lives in `targetOrDefault`.
- Existing callers of `this.target` (`OptimizeMojo`, `SummaryMojo`, `Timings`,
  `withDocker`, `dockerCommand`) keep working unchanged; `mount()` already
  absolutizes, so the fix is idempotent there.
- `mvn -Pqulice` is the linter source of truth (repo convention).
- No Cyrillic in added diff lines.

## Review Focus

1. A configured relative target (`-Dhone.target=target`) with no project: the
   same `cd` bug, so both branches must absolutize.
2. `hone.timings` file path `target.toPath().resolve(...)` after the change:
   still writes inside the same directory, only under an absolute prefix.
3. `skipIfNoClasses` early return (`OptimizeMojo.java:392`) deletes
   `hone-statistics.csv` under the absolutized target — same file.
4. `localPaths(target, ...)` prefix rewrite: an absolute target makes the
   `INCLUDES`/`EXCLUDES` globs absolute, which is what jeo needs.
5. Windows: `getAbsoluteFile()` on a `\target` path must not break
   `localPaths`' `^[/\\]target` prefix regex, which matches before rewriting.
